## 整体结构

```
┌─────────────────────────────────────────────────────────┐
│  浏览器                                                   │
│  http://127.0.0.1:8000                                   │
└───────────────────────┬─────────────────────────────────┘
                        │ 单进程，前后端同源
┌───────────────────────▼─────────────────────────────────┐
│  文枢后端（FastAPI，uvicorn）                              │
│                                                          │
│  /api/projects      作品、人物、大纲、章节                 │
│  /api/polish        文本重塑（本工程补齐注册）             │
│  /assets  /*        前端静态资源（构建产物）                │

        │                              │
┌───────▼────────┐          ┌──────────▼─────────────────┐
│  SQLite        │          │  engine/  文本重塑引擎       │
│  runtime/data/ │          │                             │
```

## 为什么这样组织

### 单进程同源

前端构建产物直接落在 `backend/static`，由后端一并服务。
好处是没有跨域、没有第二个端口、不需要反向代理。

代价是改前端必须重新 `npm run build`。

### engine 独立成目录

`engine/` 下的模块**不依赖 FastAPI、不依赖后端任何代码**，只依赖标准库
（改写与体检部分）与 litellm（模型调用部分）。

这样做的理由：

1. 可以在命令行直接调用，不必起服务；
2. 桥接层（`backend/app/services/rewrite_engine.py`）只需把目录挂到
   `sys.path` 再转发，耦合极低；
3. 将来若要把引擎单独发布或替换实现，不影响后端。

### 运行时数据在代码目录之外

`runtime/data` 与 `runtime/logs` 由 `.env` 中的绝对路径指定，
不在 `backend/` 内。这样更新代码不会碰坏已有作品。

## 子代理调度

主 Agent 交互，子代理做后端推理。**不新增接口**——复用同一个 `chat-stream`，
因为前端只订阅这一条流，另开接口不会自动接入时间线。

```
chat-stream
    └─ 主 Agent 工具循环
          └─ dispatch_subagents（内部工具，risk_level=0 只读）
                └─ 有界并发执行子任务
                      ├─ 逐个子任务转发 step_start / step_update
                      └─ 只把摘要回给主 Agent
```

### 职责划分

| 角色 | 做什么 | 不做什么 |
| :--- | :--- | :--- |
| 主 Agent | 与用户交互、拆解任务、派发、汇总 | — |
| 子代理 | 只读推理，返回结构化发现 | 不写库、不持有 db 会话、不持有任何工具 |
| 主流程 | 读取章节固化快照、存步骤、转事件 | — |

### 只读保证

子任务拿到的只是**主流程读取并固化的文本快照**，它：

- 没有数据库会话
- 没有项目写工具
- 没有 MCP 工具

模型调用显式关闭工具自动加载与执行：

```python
generate_text(
    ...,
    tools=None,               # 不注入任何工具
    tool_choice="none",       # 明确禁止工具选择
    auto_mcp=False,           # 不自动加载 MCP
    handle_tool_calls=False,  # 不自动执行工具调用
)
```

后两项默认是**开启**的，必须显式关掉。

### 事件职责

- 子任务只产出内部进度（`start` / `done` / `error` / `all_done`）
- `_dispatch_subagents_stream` 统一转换成 `step_start` / `step_update` 并保存步骤
- `final_*` 只由主 Agent 发送

### 预算（从第一版生效）

| 项 | 默认值 |
| :--- | :--- |
| 整轮最多子任务 | 3 |
| 并发上限 | 3 |
| 单任务输出 token | 4000 |
| 单任务输入字符 | 20000 |
| 单任务重试 | 1 |
| 整轮超时 | 180s |

重复派发与重试**共享同一份整轮预算**，模型无法通过反复派发绕过限制。
预算账本 `TurnBudget` 挂在会话上。

### 结果形式

```json
{
  "task_id": "...",
  "status": "completed | failed | cancelled",
  "findings": [
    {
      "summary": "人物年龄前后不符",
      "severity": "warning",
      "source_refs": [{"kind": "chapter", "id": "c1", "label": "第1章", "excerpt": "..."}]
    }
  ],
  "source_refs": [...],
  "usage": {"prompt_tokens": 100, "completion_tokens": 50},
  "error": "",
  "unchecked": ["时间线未检查"]
}
```

`unchecked` 用于区分「检查过没问题」与「没看」——
缺了它就无法判断报告是否完整。

回给主 Agent 的是 `to_summary()` 的摘要版本，
完整结果留在步骤记录里，避免多个长结果挤占主上下文。

### 保存范围

「子代理只读」是指**不修改作品**。
步骤与检查结果仍由主流程写入 `AgentExecutionStep` 与 `AgentToolCall`，
因此重新打开对话仍可查看。

### 失败与停止

- 单个任务失败：保留其他结果，标注未完成部分
- 用户停止或连接断开：取消并等待全部子任务结束，再收尾记录
- 首期不做脱离对话继续运行的后台任务

## 数据流：一次改写

```
用户在界面粘贴文本
        │
        ▼
POST /api/polish  { original_text, mode, use_model }
        │
        ├──► 改写前体检  engine.text_diagnostics
        │
        ├──► use_model = true
        │      │
        │      ├─ 取提示词模板 AI_DENOISING
        │      ├─ 调模型
        │      └─ 失败 → 回退本地规则
        │
        └──► use_model = false
               │
               └─ engine.local_rewriter.rewrite_local
                  （逐条规则表，输出完全由输入决定）
        │
        ├──► 改写后体检
        │
        ▼
返回 { original_text, polished_text, engine, diagnostics_* }
        │
        │  ⚠ 原稿未被修改，只返回候选稿
        ▼
用户点「采纳」→ POST /api/polish/accept → 写入 runtime/data/accepted/
        │
        └──► 版本链保留，可 POST /api/polish/rollback 回退
```

## 任务隔离机制

改写过程可能被中断，中断后重跑需要跳过已完成的块。判断「哪些块已完成」
必须与**输入内容**绑定，否则换一篇稿件时会复用上一稿的结果。

实现要点：

1. **任务目录独立**：每次改写建立独立目录，不共用路径；
2. **内容指纹**：对输入文本算 SHA256，存进进度文件；
3. **指纹校验**：载入进度时比对指纹，不一致就整体作废。

详见 `engine/aigc_round_service.py` 中的 `compute_input_fingerprint()`
与 `_load_progress_payload()`。

## 关键约束

| 约束 | 原因 |
| :--- | :--- |
| 工作目录必须是 `backend/` | `.env` 以相对路径读取 |
| `SESSION_COOKIE_SECURE=false` | 本地 HTTP，Secure Cookie 不会被发送 |
| 数据目录用绝对路径 | 避免依赖进程工作目录 |
| 不改原稿 | 原稿与候选稿分离是核心约束 |

## 扩展点

若将来需要多用户：见 [无登录改造.md](无登录改造.md) 的恢复办法。

若将来需要多模型路由：在 `engine/llm_client.py` 与后端
`app/services/ai_service.py` 之间加一层网关即可，不必改动引擎本身。
