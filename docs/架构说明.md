# 架构说明

## 整体结构

```
┌─────────────────────────────────────────────────────────┐
│  浏览器                                                   │
│  http://127.0.0.1:8000                                   │
└───────────────────────┬─────────────────────────────────┘
                        │ 单进程，前后端同源
┌───────────────────────▼─────────────────────────────────┐
│  文枢后端（FastAPI，uvicorn）                              │
│                                                          │
│  /api/projects      作品、人物、大纲、章节                 │
│  /api/polish        文本重塑（本工程补齐注册）             │
│  /assets  /*        前端静态资源（构建产物）                │
│                                                          │
│  中间件：无登录模式，回退本地身份                          │
└───────┬──────────────────────────────┬──────────────────┘
        │                              │
┌───────▼────────┐          ┌──────────▼─────────────────┐
│  SQLite        │          │  engine/  文本重塑引擎       │
│  runtime/data/ │          │                             │
│   wenshu.db    │          │  local_rewriter   去AI痕迹  │
│                │          │  text_diagnostics 文本体检  │
│  ChromaDB      │          │  aigc_round_svc   任务隔离  │
│  向量记忆       │          │  llm_client       模型调用  │
└────────────────┘          └──────────┬─────────────────┘
                                       │ 可选
                            ┌──────────▼─────────────────┐
                            │  外部模型 API               │
                            │  （不填则走本地规则）        │
                            └────────────────────────────┘
```

## 为什么这样组织

### 单进程同源

前端构建产物直接落在 `backend/static`，由后端一并服务。
好处是没有跨域、没有第二个端口、不需要反向代理。

代价是改前端必须重新 `npm run build`。

### engine 独立成目录

`engine/` 下的模块**不依赖 FastAPI、不依赖后端任何代码**，只依赖标准库
（改写与体检部分）与 litellm（模型调用部分）。

这样做的理由：

1. 可以在命令行直接调用，不必起服务；
2. 桥接层（`backend/app/services/rewrite_engine.py`）只需把目录挂到
   `sys.path` 再转发，耦合极低；
3. 将来若要把引擎单独发布或替换实现，不影响后端。

### 运行时数据在代码目录之外

`runtime/data` 与 `runtime/logs` 由 `.env` 中的绝对路径指定，
不在 `backend/` 内。这样更新代码不会碰坏已有作品。

## 数据流：一次改写

```
用户在界面粘贴文本
        │
        ▼
POST /api/polish  { original_text, mode, use_model }
        │
        ├──► 改写前体检  engine.text_diagnostics
        │
        ├──► use_model = true
        │      │
        │      ├─ 取提示词模板 AI_DENOISING
        │      ├─ 调模型
        │      └─ 失败 → 回退本地规则
        │
        └──► use_model = false
               │
               └─ engine.local_rewriter.rewrite_local
                  （逐条规则表，输出完全由输入决定）
        │
        ├──► 改写后体检
        │
        ▼
返回 { original_text, polished_text, engine, diagnostics_* }
        │
        │  ⚠ 原稿未被修改，只返回候选稿
        ▼
用户点「采纳」→ POST /api/polish/accept → 写入 runtime/data/accepted/
        │
        └──► 版本链保留，可 POST /api/polish/rollback 回退
```

## 任务隔离机制

改写过程可能被中断，中断后重跑需要跳过已完成的块。判断「哪些块已完成」
必须与**输入内容**绑定，否则换一篇稿件时会复用上一稿的结果。

实现要点：

1. **任务目录独立**：每次改写建立独立目录，不共用路径；
2. **内容指纹**：对输入文本算 SHA256，存进进度文件；
3. **指纹校验**：载入进度时比对指纹，不一致就整体作废。

详见 `engine/aigc_round_service.py` 中的 `compute_input_fingerprint()`
与 `_load_progress_payload()`。

## 关键约束

| 约束 | 原因 |
| :--- | :--- |
| 工作目录必须是 `backend/` | `.env` 以相对路径读取 |
| `SESSION_COOKIE_SECURE=false` | 本地 HTTP，Secure Cookie 不会被发送 |
| 数据目录用绝对路径 | 避免依赖进程工作目录 |
| 不改原稿 | 原稿与候选稿分离是核心约束 |

## 扩展点

若将来需要多用户：见 [无登录改造.md](无登录改造.md) 的恢复办法。

若将来需要多模型路由：在 `engine/llm_client.py` 与后端
`app/services/ai_service.py` 之间加一层网关即可，不必改动引擎本身。
