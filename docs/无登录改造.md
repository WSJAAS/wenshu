# 无登录改造

本工程定位为**本地单人使用**，因此去掉了多用户登录。

本文记录改造点与恢复办法。

---

## 改了什么

### 后端：`backend/app/middleware/auth_middleware.py`

**上游行为**：从签名 Cookie `session_token` 解析用户，解析不到就令
`request.state.user_id = None`。各接口的 `require_login` 依赖据此返回 401。

**本工程行为**：无有效会话时，回退为一个固定的本地用户身份：

| 项 | 值 |
| :--- | :--- |
| user_id | `local_<md5("local")[:16]>` |
| 用户名 | `local` |
| 显示名 | 本机用户 |
| 权限 | 管理员 |

这个用户会在首次请求时自动入库（复用上游 `create_or_update_from_linuxdo`，
传 `local_` 前缀的 id 会被识别为本地用户）。

**保留的行为**：

- 请求若确实带了有效会话 Cookie，仍按该用户身份处理——便于将来恢复多用户。
- 提示词工坊的跨实例代理请求逻辑不变。
- 被禁用的用户（`trust_level = -1`）依然会被拒绝。

### 前端：`frontend/src/components/ProtectedRoute.tsx`

**上游行为**：调用 `authApi.getCurrentUser()` 判断登录态，未登录跳转 `/login`。

**本工程行为**：直接渲染子组件，不做检查。

---

## 为什么这样做

1. 本地单人使用，不存在多租户隔离需求；
2. 上游的会话机制为多用户设计，单人场景下反复过期影响体验；
3. 上游 `require_login` 检查的是 `request.state.user` **对象**而非 id，
   所以回退时必须提供真实 User 对象，不能只设一个 id 字符串。

---

## 影响范围

**没有改动**：

- `backend/app/api/auth.py`（登录接口仍在，只是不再强制）
- `backend/app/security.py`（会话签名逻辑不变）
- 任何数据模型的 `user_id` 字段

**这意味着**：

- 数据仍带 `user_id`，将来恢复多用户时，本地用户的作品归其名下；
- 若之前用过上游版本，原有账号数据仍可通过登录接口访问。

---

## 如何恢复登录

### 后端

编辑 `backend/app/middleware/auth_middleware.py`，
把「无有效会话」分支改回：

```python
        # --- 无有效会话：回退本地身份（本工程的默认路径）---
        local_user = await _ensure_local_user()
        request.state.user_id = LOCAL_DEFAULT_USER_ID
        request.state.user = local_user
        request.state.is_admin = True
        return await call_next(request)
```

改为：

```python
        # --- 无有效会话：视为未登录 ---
        request.state.user_id = None
        request.state.user = None
        request.state.is_admin = False
        return await call_next(request)
```

### 前端

把 `frontend/src/components/ProtectedRoute.tsx` 换回上游实现：
恢复 `authApi.getCurrentUser()` 检查与 `/login` 跳转。

### 配置

在 `backend/.env` 中设定真实的登录账户：

```ini
LOCAL_AUTH_ENABLED=true
LOCAL_AUTH_USERNAME=你的用户名
LOCAL_AUTH_PASSWORD=你的密码
SESSION_COOKIE_SECURE=false   # 本地 HTTP 必须为 false
```

## 安全提示

无登录模式下，**任何能访问该端口的人都拥有完整权限**。

因此：

- 后端默认绑定 `127.0.0.1`，仅本机可访问；
- **不要**把该端口暴露到公网；
- 如需局域网访问，请先恢复登录，或加一层反向代理鉴权。
